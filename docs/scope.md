# 범위와 설계 원칙

## 이 프로젝트가 하는 일

**정밀하지만 비파괴적인 진단까지**가 syschk 의 목적이다.
시스템의 상태를 정확히 관찰하고, 수치의 의미를 해석하고, 원인 가설을 좁혀 제시한다.

## 이 프로젝트가 하지 않는 일

**적극적이고 능동적인 장애 해결은 범위에 포함하지 않는다.**

- 설정 파일을 고치지 않는다
- 서비스를 시작·중지·재시작하지 않는다
- 패키지를 설치·삭제하지 않는다(설치 **명령을 보여줄** 뿐이다)
- 파일시스템을 검사·수정하지 않는다
- 커널 파라미터·전력 상한·펌웨어 설정을 바꾸지 않는다
- 프로세스를 종료하지 않는다

### 왜 그런가

이 앱의 주 사용자는 초보자다. **진단 도구를 쓰다가 오히려 시스템을 망치는 일이 발생해서는 안 된다.**
자동 복구는 상황을 잘못 읽었을 때 피해가 즉시 발생하고, 되돌리기 어렵고, 초보 사용자가
무슨 일이 벌어졌는지 이해하기 어렵다. 진단과 복구를 분리하면 최악의 경우에도 잃는 것이 없다.

### 그래도 가치가 있는 이유

장애 복구의 대부분은 "무엇이 문제인지 모른다"에서 막힌다.
**시스템이 어떤 상태인지 명확히 이해하는 것만으로 복구 전 단계까지는 이미 큰 진전이다.**
원인을 알면 조치는 검색으로도, 다른 사람의 도움으로도 할 수 있다. 반대로 원인을 모르면
어떤 조치도 도박이 된다. syschk 는 그 "아는 단계"까지를 확실히 책임진다.

조치가 필요한 경우 syschk 는 **무엇을 하면 되는지 명령과 설정 내용을 보여준다.** 실행은 사용자가 한다.

## 안전 보장 방식

원칙을 문서로만 적어두지 않는다. 코드가 강제한다.

- 외부 명령은 `ReadOnlyCommand` 로만 만들 수 있고, 생성 시점에 프로그램별 읽기 전용 정책을 통과해야 한다
- 허용 목록에 없는 프로그램은 실행 자체가 불가능하다
- 조회와 변경이 섞인 도구는 서브커맨드·인자 단위로 좁힌다
  (`systemctl status` 는 허용, `systemctl restart` 는 거부. `dmesg -T` 는 허용, `dmesg -C` 는 거부)
- 안전 인자를 강제한다(`fsck` 는 `-N` 없이는 실행 불가, `fstrim` 은 `--dry-run` 필수)
- `tests/policy.rs` 가 카탈로그의 모든 명령을 검증하고, 파괴적 명령이 거부되는지도 검증한다
- 사용자는 `syschk policy` 로 이 정책 전체를 직접 확인할 수 있다

자세한 구조는 [architecture.md](architecture.md#읽기-전용-게이트) 참조.

## 설계 원칙

1. **사용자는 명령을 기억하지 않는다.** 화면은 목적으로, 메뉴는 작업으로 구성한다. 도구 이름은 메뉴 레이블에 쓰지 않는다.
2. **명령은 기억 대상이 아니라 근거다.** 기본은 접힌 상태이며 `c` 로 펼친다. 보고서에는 항상 포함된다. 그 결과로 사용자는 쓰다 보면 배우게 된다.
3. **판정에는 근거를 붙인다.** "정상" 대신 "정상 — 스왑 사용 0 B, 스래싱 흔적 없음"처럼 수치와 기준을 함께 제시한다.
4. **모르는 것은 모른다고 말한다.** 신뢰할 수 없는 센서·미설치 도구는 "계측 불가(이유)"로 표시한다. 추정치를 사실처럼 보여주면 진단을 망친다.
5. **없는 것도 정보다.** 오류 로그가 0건이라는 사실, 전원 레코드가 노출되지 않는다는 사실은 그 자체로 결론을 좁힌다.
6. **막히면 길을 알려준다.** 도구가 없어서 진단이 멈추지 않게 한다. 무엇이 없고, 그것이 무엇을 해주며, 어떻게 설치하는지 안내한다.
7. **읽기 전용이 기본이며 예외가 없다.** 조치는 제안으로만 제시한다.
8. **최소 권한.** `sudo` 가 필요한 항목은 미리 표시한다. 권한이 없으면 해당 항목만 비활성이고 나머지는 정상 동작한다. 앱이 내부에서 `sudo` 를 호출하지 않는다.
9. **결론은 단정이 아니라 좁혀진 가설 목록.** 배제된 것, 약화된 것, 남은 것을 구분해 보여준다.
10. **확장이 쉬워야 한다.** 새 진단 항목 추가가 기존 코드 수정이 아니라 등록으로 끝나야 한다.

## 범위에서 제외

- 시스템 설정 자동 변경, 서비스 자동 재시작, 패키지 자동 설치 — 위 이유로 영구 제외
- 중앙 집중 모니터링·시계열 DB·장기 보관 (Prometheus/Grafana 의 영역)
- 알림 발송 — `syschk check` 의 종료 코드로 외부 도구와 연계
- 침해 사고 대응 전문 기능(포렌식 이미지 획득 등)
- 다국어 UI — 초기 단계에서는 영어로 통일한다
- Ubuntu 이외 배포판 정식 지원
