# 개발 계획

각 마일스톤은 **화면 단위**로 끝난다. 완료 기준은 "그 화면으로 실제 진단이 되는가"다.

| 마일스톤 | 기간 | 화면 | 상태 |
| --- | --- | --- | --- |
| M0 골격 | 1주 | 전체 구조, 14 · 도구 준비 | ✅ 완료 |
| M1 실시간 관찰 + 병목 특정 | 3주 | 1 · 2 | ✅ 완료 |
| M2 저장 공간·저장장치 | 2주 | 4 | 다음 |
| M3 로그·회고 지표 | 3주 | 11 · 3 | 예정 |
| M4 서비스·부팅·프로세스 | 2주 | 6 · 7 | 예정 |
| M5 네트워크 | 2주 | 5 | 예정 |
| M6 하드웨어·보안·패키지·컨테이너 | 3주 | 8 · 9 · 10 | 예정 |
| M7 계측 준비·보고서·비대화형 | 2주 | 12 · 13 | 예정 |
| M8 완성도 | 2주 | 전체 | 예정 |

합계 약 20주. M2·M3·M5 는 서로 독립적이라 병행 가능하다.

## M0 — 골격 ✅

계약 정의(`Task` / `Tool` / `Probe` / `ReadOnlyCommand`), 작업·도구 레지스트리, 이벤트 루프,
홈 메뉴 14화면 라우팅, 증상 검색, 도구 준비 화면, `doctor` / `tasks` / `check` / `policy` CLI, 시험과 CI.

완료 기준과 결과:

| 기준 | 결과 |
| --- | --- |
| 홈에서 14개 화면 이동, 정상 종료 | 됨 (`tests/ui.rs`) |
| 증상 검색 동작 | 됨 — "disk full", "frozen", "oom" 등 15개 사례 시험 |
| 도구 설치 상태 점검 | 됨 — 55개 도구, `syschk doctor` |
| 읽기 전용 보장 | 됨 — 카탈로그 245개 명령 전수 검증, 파괴적 명령 60여 개 거부 시험 |

## M1 — 실시간 관찰 + 병목 특정 (화면 1, 2) ✅

CPU·메모리·디스크 I/O·네트워크·프로세스 수집기(`/proc` 직접 읽기), 압박 지표(PSI) 기반 병목 판정,
프로세스 상위 목록과 정렬·고정·정지, 표본 추출 파이프라인.

완료 기준과 결과:

| 기준 | 결과 |
| --- | --- |
| `top` / `iostat` / `free` 와 값이 일치 | 확인 — load 9.54 = `uptime` 9.54, 메모리 사용 23.0G / 여유 481G ≈ `free -m` 23.8G / 491G, CPU user 18% · sys 4.7% ≈ `mpstat` 17.1% · 4.25% |
| 올바른 병목 축 특정 | 규칙 표 시험 13건으로 검증 (`tests/bottleneck.rs`) — 부하를 인위로 만들지 않고 지표 조합으로 확인 |
| 유휴 CPU 1% 미만 | 실시간 화면이 아닐 때는 **표본을 아예 뜨지 않는다**(0%). 실시간 화면에서는 1.5초 간격 · 표본당 16ms(프로세스 676개) ≈ 코어 하나의 1.1% |
| 상주 메모리 | 3.6MB (목표 50MB 미만) |

구현에서 내린 선택:

- **외부 도구를 쓰지 않는다.** `/proc` 를 직접 읽으므로 `sysstat` 이나 `iotop` 이 없어도 동작한다.
  화면에는 "직접 해보려면 이 명령을 쓰면 된다"로 `mpstat`·`iostat`·`pidstat` 을 함께 안내한다.
- **비동기를 도입하지 않았다.** 표본 하나가 16ms 로 끝나므로 UI 를 막지 않는다.
  느린 수집기(`smartctl` 등)가 등장하는 M2 에서 도입한다.
- **오류와 드롭을 구분한다.** 네트워크 드롭은 정상 시스템에서도 늘어나므로(받을 사람이 없는
  패킷도 집계된다) 경고 근거로 쓰지 않는다. 실제 검증 중 이 구분 없이는 오탐이 났다.
- **`-` 와 `0` 을 구분한다.** 다른 사용자 프로세스의 I/O 는 권한 없이 읽을 수 없다. 0 으로
  꾸미지 않고 "읽지 못했다"로 표시한다.
- **표본 비용을 화면에 표시한다.** 관찰에도 비용이 든다는 사실을 숨기지 않는다.

## M2 — 저장 공간·저장장치 (화면 4) — 다음

디렉터리 용량 드릴다운, 삭제 후 점유 탐지, inode 판정, SMART/NVMe 요약, RAID/LVM 구성.
느린 수집기가 처음 등장하므로 비동기 수집을 도입한다.

완료 기준: 공간 부족 4가지 원인 유형(대용량 디렉터리 / 삭제 후 점유 / inode / 로그)을 시나리오별로 구분.

## M3 — 로그·회고 지표 (화면 11, 3)

부팅 세션 탐색, 비정상 종료 판정, 반복 노이즈 집계·접기, 장애 패턴 프리셋,
타임스탬프 형식 정규화, `sar` 구간 조회.

완료 기준: 정지 시각 구간 확정과 자원 고갈 항목별 배제를 앱 조작만으로 도출.

## M4 — 서비스·부팅·프로세스 (화면 6, 7)

실패 유닛 원인 요약, 부팅 시간 분해, 프로세스 심층(파일·한계·대기 지점·추적).

완료 기준: 의도적으로 실패시킨 유닛의 원인을 한 화면에서 파악.

## M5 — 네트워크 (화면 5)

계층 순차 판정(링크 → IP → 경로 → 외부 → 이름해석 → 응용), 오류·재전송 카운터,
방화벽 대조, 제한적 패킷 캡처.

완료 기준: 링크 다운 · 경로 없음 · DNS 실패 · 방화벽 차단 4가지를 각각 정확히 지목.

## M6 — 하드웨어·보안·패키지·컨테이너 (화면 8, 9, 10)

ECC·센서 신뢰성 판별, GPU 상태, 접속 이력·노출 점검, 업데이트 상태, 컨테이너 자원.

완료 기준: 하드웨어 인벤토리 재현, 미검증 센서가 수치로 노출되지 않음.

## M7 — 계측 준비·보고서·비대화형 (화면 12, 13)

포렌식 준비 점검표와 설정 제안, Markdown/JSON 출력, 마스킹, `check` 종료 코드 규약, 지표 기록 세션.

완료 기준: 보고서에 실행 명령·원본 출력·판정·가설 분류가 모두 포함되고 재현 가능.

## M8 — 완성도

용어 설명과 도움말 보강, ASCII·저색상 폴백 검증, 설정 파일, 비전문가 사용성 시험, 릴리스 바이너리.

심화 프로파일링([commands.md](commands.md) R절)은 M8 이후 선택 확장으로 둔다.

## 검증 전략

| 계층 | 방법 |
| --- | --- |
| 파서 | `tests/fixtures/` 에 실제 명령 출력을 저장해 회귀 시험. 배포판·버전별 차이를 고정 |
| 판정 규칙 | 지표 조합 → 기대 판정을 표 기반 시험으로 검증 |
| 읽기 전용 | 카탈로그 전수 검증 + 파괴적 명령 거부 시험 (`tests/policy.rs`) |
| 작업 흐름 | 실제 장애 기록을 픽스처로 만들어 같은 결론에 도달하는지 종단 시험 |
| 시나리오 | 컨테이너·VM 에서 장애 인위 재현(디스크 채우기, OOM, 링크 다운, 유닛 실패, inode 고갈) |
| 도구 안내 | 도구를 제거한 환경에서 안내·대체 경로 확인 |
| UI | `ratatui` `TestBackend` 렌더 검증 (80×24 포함) |
| 권한 | 비권한 사용자 전체 실행 — 앱이 죽지 않고 해당 항목만 비활성인지 확인 |
| 사용성 | 비전문가에게 증상 문장만 주고 목표 화면 도달 시간 측정(NFR-9) |

## 위험과 대응

| 위험 | 영향 | 대응 |
| --- | --- | --- |
| 명령 출력 형식이 배포판·버전마다 다름 | 파싱 실패 | 픽스처 회귀 시험, 실패는 격하 처리하고 원본은 표시 |
| 지원 명령이 많아 유지보수 부담 | 확장 지체 | `Probe` 단위 격리와 등록 기반 확장(NFR-10) |
| `sudo` 필요 항목 다수 | 반쪽 기능 | 비권한 경로 우선 사용, 필요 권한 사전 표시 |
| 센서·전압값 신뢰성 | 잘못된 판정 유도 | 화이트리스트 — 검증된 드라이버만 수치 노출, 나머지는 `Untrusted` |
| 느린 수집이 UI 를 막음 | 응답성 저하 | M2 에서 비동기 도입, 캐시와 명시적 갱신, 진행 표시 |
| 결론 과신 | 오진 | 결론은 가설 분류로만 제시, 단정 표현 금지 |
| 메뉴 문구가 비전문가에게 안 닿음 | 도달 실패 | 증상 표현 별칭을 검색 색인에 등록, 사용성 시험으로 보완 |
